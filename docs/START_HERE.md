# ChopTree · AI 工作固定入口

> 这是每次**新对话 / 新任务**读取项目知识的第一个文件。适用于通过 ChatGPT 管理的 GitHub 项目 `119shenhao/choptree`，默认分支 `main`。
> 此文档本身不会被 ChatGPT 自动读取；必须通过 ChatGPT「砍树游戏」项目指令或用户显式要求，让 AI 先打开这里。

## 必须按顺序进行

1. 读取本文件，确认仓库、分支以及下列导航。
2. 读取 [PROJECT_STATUS.md](./PROJECT_STATUS.md)，确认已完成、未完成、当前任务、阻塞项和下一步。
3. 读取 [WORKFLOW.md](./WORKFLOW.md)，判断本次任务类型。
4. 按流程选择相关文档，而不是无差别地通读所有文件：
   - 想法 / 不确定事项 → [IDEAS_INBOX.md](./IDEAS_INBOX.md)
   - 已确认的需求 → [REQUIREMENTS.md](./REQUIREMENTS.md)
   - 重要技术或流程决策 → [DECISIONS.md](./DECISIONS.md)
   - 执行记录 / 验证 / 中断交接 → [WORK_LOG.md](./WORK_LOG.md)
5. 仅在必要时读取相关源代码、配置和历史提交；以 GitHub **最新实际状态**为准，不用聊天记忆替代核验。
6. 工作过程中按 [WORKFLOW.md](./WORKFLOW.md) 的“主动识别与记录”规则保存信息；每个关键里程碑验证提交结果。
7. 结束前更新状态与交接信息；向用户报告已提交的文件、Commit SHA、已验证内容和待办事项。

## 执行底线

- **AI 主动识别**：用户无需反复提醒「记下来」；重要且确定的决定应及时记入正式文档；可能重要但未定的想法先记候选，再视情况提问确认。
- **不推断用户已批准**：待讨论、已确认、已实现、已验证要分开；模糊事项不能擅自升级为正式需求。
- **保护原有内容**：读取并保留已有记录；变更注明日期、来源、状态，尽量按主题局部修改。
- **不声称未完成的操作已经完成**：GitHub 提交成功与代码测试通过分别验证；失败直接说明。
- **不假装后台常驻**：只能在实际处理对话/任务期间读写，不会因为用户关闭聊天而自动触发保存。
- **高风险事项先确认**：删除数据、不可逆操作、生产配置和敏感信息等不因文档工作流获得默认批准。
