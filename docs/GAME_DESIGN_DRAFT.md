## 一、设计目标

- 平台已确认：纯 HTML5 小游戏。
- 操作方向：用户倾向**以手动点击砍树为主**；已确认采用**独立的「砍树」按钮**（REQ-0007），且**按住可连续砍伐**（REQ-0008），而非直接点击树木。是否在未来加入自动玩法仍未定。
- V0.1 目标（建议）：用极小的可玩循环测试「点击反馈是否爽快」「资源增长与升级是否有动力」，暂不追求复杂内容。
- 本阶段产出：确定玩法方向、界面结构和第一版边界的讨论稿；**不创建游戏代码、不部署**。

## 二、核心循环（建议，未确认）

1. 玩家操作画面上的独立 **「砍树」按钮**砍伐；**长按可以连续砍伐**（这两点已确认）。建议保留「短按一次砍一下、松开停止连砍」的常见操作，但具体触发/停止细节和连砍速度尚未正式确认。
2. 树木减少生命值或累积砍伐进度，给出明显反馈（晃动、木屑、数字或音效，可选）。
3. 砍倒后获得木材，自动出现下一棵树，减少重复操作。
4. 斧头升级与砍树速度作为**相互独立的设计维度**（已确认分开，REQ-0009）；**斧头升级主要增加伤害与砍伐范围**（已确认方向，REQ-0010），但范围的实际含义、成长方式、资源消耗，以及如何单独提升砍树速度仍待讨论。
5. 重复以上过程。是否解锁树种/区域、如何解锁，由后续设计讨论决定。

这里的「木材」「斧头升级」「树木生命值」都是**方案提议**，不是已经确认的功能。

## 四、第一版功能范围候选（未确认）

**建议纳入最小原型：**
- 通过单独的「砍树」按钮触发手动砍伐，**按住可连续砍伐**（输入方式已确认）；即时视觉反馈、短按和松开细节、连砍频率为待讨论的设计建议。
- 一种基础树木和简单的砍倒/重生循环。
- 木材资源累计与消耗。
- 斧头升级入口与独立砍树速度数值（两者分开已确认）；斧头升级主要增加**伤害与范围**已确认，但具体范围机制、数值、升级消耗及砍树速度成长方式仍待确认。
- 基础本地存档（例如浏览器刷新后保留进度）。
- 可在手机浏览器顺畅操作的布局。

**建议暂缓：** 工人自动砍树、离线收益、任务/成就、多人、排行榜、登录、支付、广告、复杂地图、云端存档。另将用户提出的**更大范围的特殊道具或类似炸弹的游戏物品**保留为后续候选（IDEA-0003），**未确认纳入第一版**。暂缓不等于永远不做。

## 五、数值和成长的设计思路（已确认原则 + 待讨论细节）

**已确认：砍树速度与斧头升级分开管理（REQ-0009）。** 不把砍树速度直接视为斧头等级的附属值，也不因斧头等级变化就默认改变砍伐频率。

**待讨论的设计举例（不是已确定玩法）：**

| 设计维度 | 可能的含义 | 未确定事项 |
| --- | --- | --- |
| 砍树速度（独立数值） | 可表示长按时单位时间内的砍伐次数 | 单位、初始值、提升方式、是否可升级、上限或节奏限制 |
| 斧头升级（独立维度） | **已确认主要提高砍伐伤害与砍伐范围** | “范围”具体表示同时作用于多棵树、命中区域或其他含义；两项的增长规则、等级与费用均待确认 |
| 后续范围性道具（仅候选） | 可考虑更大范围的砍伐物品或类似炸弹的游戏效果 | 具体物品类型、触发方式、是否消耗、解锁条件和加入版本均未定 |

*已确认的分工是：速度与斧头升级独立，斧头升级主要提高伤害与范围。速度是否表示每秒砍伐次数、范围如何作用于树木，均仍待确认。*


- 砍伐体验：每次有效点击推进进度；避免频繁无反馈点击。
- 成长体验：砍树获得资源，升级后同等点击量可完成更难的树。
- 节奏目标：开局快速获得一次「砍倒—奖励—升级」体验，再逐渐增加目标。
- **暂不确定具体数值：** 砍树速度的单位和初始值、升级方式、初始伤害、生命值、木材收益、升级价格、解锁门槛等，在玩法认可后再列出可调整的数值表。

## 六、待确认的核心问题

1. **核心交互已确定：** 使用独立的「砍树」按钮（REQ-0007），**长按可连续砍伐**（REQ-0008）；**砍树速度与斧头升级分开**（REQ-0009）。**仍待讨论：** 短按和松开规则、速度的独立提升方式与数值单位、是否另有体力限制。
2. **画面表现：** 竖屏/横屏、卡通/像素等方向。
3. **成长主线：** 斧头升级主要加伤害与砍伐范围（已确认）；**首先需要澄清「范围」是一次能砍到多棵树，还是单棵树上的命中范围**。再讨论速度如何独立成长，以及是否加入人物、工具耐久、树种/场景解锁。
4. **后续特殊物品候选：** 大范围道具或类似炸弹的效果（IDEA-0003）要如何触发、消耗、获得，以及何时加入？这些尚未批准。
5. **节奏深度：** 纯主动点击；或未来加入少量辅助技能（不等同自动挂机）。
