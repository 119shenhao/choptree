# ChopTree · 游戏设计草案 V0.1（讨论稿）

> 2026-11-21 建立。**状态：待讨论 / 未批准实施。** 这是一份先设计、后确认、再开发的讨论稿，不代表用户批准其中具体玩法或美术方案；本阶段禁止直接编写游戏代码。
>
> **信息来源区分：** 用户表示游戏「应该是偏手动点击的」，要求「先别直接开始写，先设计、记录」，随后明确选择使用**独立的「砍树」操作按钮**（[REQ-0007](./REQUIREMENTS.md)）且**按住按钮可连续砍伐**（[REQ-0008](./REQUIREMENTS.md)）。用户也明确要求**砍树速度为独立数值，与斧头升级分开**（[REQ-0009](./REQUIREMENTS.md)），并确认**斧头升级主要提升伤害与砍伐范围**（[REQ-0010](./REQUIREMENTS.md)）。用户进一步明确：**「范围」是以游戏内方格计算的 N×N 多树同步受击区域**，**炸弹与树木是不同对象，炸弹为消耗品、放置后爆炸并造成一次性范围伤害，同级覆盖范围大于斧头**（[REQ-0011](./REQUIREMENTS.md)）；炸弹加入版本未定，其他更大范围道具仍为候选（[IDEA-0003](./IDEAS_INBOX.md)）。**2026-11-21 重要纠偏：游戏是类似《星露谷物语》的可操纵人物移动的 2D 地图玩法，角色要走到树旁真正挥斧砍伐，而不是固定站桩选树后点按钮减血（[REQ-0012](./REQUIREMENTS.md)）。**此前以“选中树木”为范围中心的设定，需在角色真实移动/挥斧的前提下确定怎样取得砍伐目标，不应误写为必须点击地图选树。其余机制、界面与数值均为 AI 供讨论的建议。关联 [IDEA-0001 / IDEA-0002](./IDEAS_INBOX.md)、[REQ-0006](./REQUIREMENTS.md)。

## 一、设计目标

- 平台已确认：纯 HTML5 小游戏。
- **玩法形态（已确认）：** 2D 平面地图上有能由玩家直接操纵移动的人物，玩家移动到树木附近，让人物实际挥斧砍伐，参考《星露谷物语》的**操作体验**而非复刻具体画面或系统（REQ-0012）。
- **砍伐输入（已确认）：** 独立「砍树」按钮（REQ-0007），按住可连续砍伐（REQ-0008）；这属于角色动作输入，**不是角色固定在原地、从地图点树后只加数字**。具体移动控件（摇杆/方向键/键鼠）、人物面向及攻击目标判定尚未定；未来是否加入自动玩法也未定。
- V0.1 目标（建议）：用极小的可玩循环测试「点击反馈是否爽快」「资源增长与升级是否有动力」，暂不追求复杂内容。
- 本阶段产出：确定玩法方向、界面结构和第一版边界的讨论稿；**不创建游戏代码、不部署**。

## 二、核心循环（建议，未确认）

1. **玩家操纵 2D 场景中的人物在地图上实际移动，靠近树木进行砍伐（已确认）**。砍伐动作由独立 **「砍树」按钮**触发；**长按可以连续挥斧（已确认）**。建议「短按一次挥斧、松开停止连续动作」，但详细节奏、移动控制方式、动作表现及移动中能否砍伐仍待确认。
2. **斧头对以当前砍伐目标树所在格为中心的 N×N 方格区域内多棵树同时造成伤害（此前已确认）**；在本轮已确认的角色自由移动玩法中，**目标树如何通过人物靠近/面向/操作来判定仍待明确**，不能默认要求玩家先点击地图树木“选中”后原地砍伐。具体 N 值、地图边缘处理和偶数 N 时中心取法尚未确定。树木生命值或砍伐进度及晃动、木屑、数字或音效等反馈属于候选表现。
3. 砍倒后获取木材、地图中树木补充或刷新作为候选成长循环；已有多棵树的方格场景，不再默认画面只存在一棵树。具体奖励与刷新规则尚未确认。
4. 斧头升级与砍树速度作为**相互独立的设计维度**（REQ-0009）；**斧头升级主要提高单次伤害和 N×N 方格覆盖区域**（REQ-0010），格数与成长公式、成本、独立速度成长方式待定。
5. 重复以上过程。是否解锁树种/区域、如何解锁，由后续设计讨论决定。

**另外已确认炸弹的基本玩法（REQ-0011）：** 炸弹和树木属于不同游戏对象；炸弹为消耗品，放置后爆炸，对爆炸覆盖范围内的树木造成一次性伤害；在同级别参照下，其范围比斧头更大。炸弹如何获得、在哪一版出现、何时爆炸、强度和范围数值均待定。

这里的「砍倒获得木材」「树木生命值形式」「树木刷新」等仍属**方案提议**，不是已经确认的功能。

## 四、第一版功能范围候选（未确认）

**建议纳入最小原型：**
- 玩家在 2D 方格地图上**操纵角色移动到树附近，由人物挥斧砍伐**（已确认）；独立的「砍树」按钮与长按连续砍（已确认）。角色移动控制、目标判定、攻击方向、动画、即时视觉反馈、短按和松开细节仍待设计。
- 方格地图中存在多棵树；斧头的一次攻击让 N×N 方格内所有树木同时受到伤害（规则已确认）；树木刷新、树种与地图大小未定。
- 木材资源累计与消耗。
- 斧头升级入口与独立砍树速度数值（两者分开已确认）；斧头升级主要增加**伤害及方格覆盖范围**，具体 N×N 格数、增长节奏、升级消耗、速度成长方式仍待确认。
- 基础本地存档（例如浏览器刷新后保留进度）。
- 可在手机浏览器顺畅操作的布局。

**建议暂缓：** 工人自动砍树、离线收益、任务/成就、多人、排行榜、登录、支付、广告、复杂地图、云端存档。**炸弹的消耗、放置、爆炸单次范围伤害和同级范围大于斧头已确认为玩法方向（REQ-0011），但尚未确定纳入第一版。**其他更大范围的特殊道具仍留作候选（IDEA-0003）。暂缓不等于永远不做。

## 五、数值和成长的设计思路（已确认原则 + 待讨论细节）

**已确认：砍树速度与斧头升级分开管理（REQ-0009）。** 不把砍树速度直接视为斧头等级的附属值，也不因斧头等级变化就默认改变砍伐频率。

**待讨论的设计举例（不是已确定玩法）：**

| 设计维度 | 可能的含义 | 未确定事项 |
| --- | --- | --- |
| 砍树速度（独立数值） | 可表示长按时单位时间内的砍伐次数 | 单位、初始值、提升方式、是否可升级、上限或节奏限制 |
| 斧头升级（独立维度） | **已确认挥斧时以角色实际砍伐的目标树为中心，N×N 方格内多棵树同时受到伤害；升级主要提高伤害与覆盖范围** | 人物移动接近及面向如何确定目标树、N×N 尺寸及变化、偶数尺寸中心处理、地图边界、等级与费用未定 |
| 炸弹（独立消耗品，已确认基本规则） | **与树不同的物品；放置后爆炸，对覆盖范围内树木造成一次性伤害；同级范围大于斧头** | 同级别对照、是否有爆炸延迟、放置方式、威力、范围尺寸/形状、获取方式及加入版本未定 |
| 其他更大范围特殊道具（候选） | 以后可能有除炸弹外的特殊清树物品 | 物品类型、触发、消耗、解锁和版本均未定 |

*已确认：速度与斧头升级独立；斧头攻击按方格对多棵树同时造成伤害；炸弹是消耗品，放置后产生更大范围的单次爆炸伤害。*


- 砍伐体验：每次有效点击推进进度；避免频繁无反馈点击。
- 成长体验：砍树获得资源，升级后同等点击量可完成更难的树。
- 节奏目标：开局快速获得一次「砍倒—奖励—升级」体验，再逐渐增加目标。
- **暂不确定具体数值：** 砍树速度的单位和初始值、升级方式、初始伤害、生命值、木材收益、升级价格、解锁门槛等，在玩法认可后再列出可调整的数值表。

## 六、待确认的核心问题

1. **核心交互已确定：** 使用独立的「砍树」按钮（REQ-0007），**长按可连续砍伐**（REQ-0008）；**砍树速度与斧头升级分开**（REQ-0009）；**范围以角色当次砍伐目标树为中心**（REQ-0010）；**玩家操纵角色在 2D 场景中移动并挥斧**（REQ-0012）。**仍待讨论：** 如何通过角色位置和面向确定砍伐目标（不默认点树选中）、短按和松开规则、速度的独立提升方式与数值单位、是否另有体力限制。
2. **2D 移动操作与画面：** 人物存在并可走动已确认；待定手机移动控件、键鼠支持、视角/画面风格、人物与树木的碰撞和角色动画、竖屏/横屏。
3. **成长主线：** 斧头升级主要加伤害和 N×N 方格多树攻击范围（已确认）；**中心位置已确认是角色当前砍伐的目标树木**（但目标如何由人物位置/朝向确定未定）；待定格数增幅（例如何时扩大一圈）、偶数尺寸中心格的处理、地图边缘、选中树的操作方式、速度如何独立成长，及树种/场景解锁。
4. **炸弹与其他特殊物品：** 炸弹作为独立消耗道具、放置后爆炸并造成一次性更大范围伤害是已确认规则（REQ-0011）；待定爆炸延迟、实际范围、同级别如何比较、伤害、获取、地图放置操作及首版是否包含。除炸弹以外的更大范围道具仍是未来候选 IDEA-0003。
5. **节奏深度：** 纯主动点击；或未来加入少量辅助技能（不等同自动挂机）。
